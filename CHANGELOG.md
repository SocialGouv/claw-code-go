## [Unreleased]

Changes since `bf21311` (last stable commit before the multi-phase port session of 2026-04-28).

### Added

- **Task graph work items.** Registry tasks carry `subject`/`active_form`/`owner` plus `blocks`/`blocked_by` dependency edges maintained reciprocally (unknown ids are explicit errors; deletion strips edges everywhere); reads derive `blocked` and `work_status` (pending/in_progress/completed vocabulary, both vocabularies parse). `task_create`/`task_update`/`task_list` expose the graph — `task_update` grows from message-append-only to full field updates including `status: "deleted"`. `todo_write` stays the flat session checklist but shares the vocabulary (optional `active_form`/`owner`/`blocks`/`blocked_by`, `"completed"` normalizes to `done`). (`internal/runtime/task/task.go`, `internal/tools/task_tools.go`, `internal/tools/todo_write.go`)
- **Real background sub-agents + runtime-defined types.** The `agent` tool now actually spawns: a child ConversationLoop runs in the background with the subagent type's toolset, streams its transcript into the task registry (`task_output` reads it live), and completion is announced through a queued `<system-reminder>` at the parent's next turn boundary — no polling. Background runs auto-deny permission asks and answer `ask_user` with an unattended notice; 10min timeout, 256KB transcript cap; a spawn with no model inherits the session model. New `define_subagent` registers a session-scoped subagent type (system prompt + tool allow-list + model override) spawnable via `agent`; built-ins can't be shadowed and children never see orchestration tools (`agent`/`define_subagent`/`workflow`/`task_stop`), so recursion is structurally bounded. (`internal/runtime/subagent.go`, `internal/tools/define_subagent.go`)
- **Oracle advisor tool.** `oracle` makes one read-only, tool-less call to a configurable stronger model (`Config.OracleModel`, settings `oracleModel`, env `CLAW_ORACLE_MODEL`; same provider as the session client; empty = session model) with the question, optional context, and up to 16 files inlined — 48KB head cap per file with a truncation marker the oracle can see; unreadable files are explicit errors; high effort requested only when the model's registry supports it. (`internal/tools/oracle.go`, `internal/runtime/oracle.go`)
- **Workflow orchestration DSL (goja).** `workflow` executes a plain-JS orchestration script on an embedded event loop: `agent(prompt, {label, subagent_type, model})` returns a Promise of a real background subagent's transcript; `parallel()`/`pipeline()` ship as a JS prelude with the documented semantics (thrown thunks/stages drop to null, pipeline has no inter-stage barrier); `phase()`/`log()` are returned with the result; `args` passes a value in; `export const meta` openers are tolerated. Guardrails: 512KB script cap, 200-agent backstop, 8 concurrent spawns, 15min default/60min max timeout with goja interrupt (busy loops die too). Workflow-spawned agents skip per-agent completion reminders — the workflow aggregates. v2 seams: schema-forced agent returns, budgets, resume. (`internal/runtime/workflow.go`, `internal/tools/workflow.go`; new deps `dop251/goja` + `goja_nodejs`)
- **semantic_search.** Local relevance-ranked code search: BM25 over overlapping 40-line windows with identifier-aware tokenization (camelCase/snake_case decomposition) — finds code by what it is ABOUT when exact strings are unknown, with zero network/credentials (an embeddings backend can later slot in behind the same tool). Skips VCS/dependency dirs and binaries, caps the scan with an explicit truncation note; read-only (classifier auto-allowed, in the explore subagent set). (`internal/tools/semantic_search.go`)
- **Behavioral prompt-parity sections.** The authored prompt grows from the single posture block into six new individually toggleable sections targeting the operating qualities Claude Code teaches natively: `communication` (final-message discipline, lead-with-outcome, `file:line` references, the `<system-reminder>` contract), `task-management` (todo hygiene, one `in_progress`, immediate completion, post-compaction reseed), `doing-tasks` (read-before-edit, anti-over-engineering, secure-by-default, professional objectivity, no time estimates), `tool-policy` (parallel independent calls, dedicated-tools-over-shell, delegate open-ended exploration, `tool_search` before claiming a capability missing), `git-safety` (the full git protocol: no config changes, no hook bypass, new-commit-not-amend, explicit staging, heredoc messages, PR flow), and `context-management` (continuation-through-summarization + the end-of-turn self-check). All original text — behavioral spec informed by published prompt captures, never copied. The identity sentence is refreshed (tool enumeration dropped). Defaults all-on; every section obeys the existing settings/CLI/frontmatter toggle surfaces. (`internal/context/sections.go`, `internal/runtime/config.go`, `internal/config/{feature,loader}.go`, `internal/runtime/conversation.go`)
- **Core tool descriptions teach usage policy.** The 11 core tools (bash, read_file, write_file, file_edit, glob, grep, todo_write, agent, ask_user, tool_search, skill) grow from one-line descriptions to short authored policy paragraphs — when to use which tool, read-before-edit, `old_string` uniqueness, stateless sub-agent prompts, ask-only-at-genuine-forks, tool_search-before-claiming-unavailable, skill-before-improvising. Tool descriptions are the primary vector the reference CLI uses to teach behavior. (`internal/tools/*.go`)
- **`<system-reminder>` injection seam + first producers.** Producers queue short harness notices; the conversation loop flushes them as ONE injected user message at the next turn boundary (consecutive user roles merge on every provider wire, tool_result ordering cannot break, `IsInjected` keeps them out of the real-turn count and off the wire). Shipped producers: post-compaction ("re-read your todo list, reconcile with the summary, don't re-ask answered questions") and plan-mode enter/exit. (`internal/runtime/reminders.go`, `internal/runtime/conversation.go`)
- **Nine-section compaction summary.** The summarization prompt becomes an authored nine-section handoff contract (`<analysis>` + `<summary>`; primary request; key concepts; files+snippets; errors and fixes; problem solving; ALL user messages with security-relevant constraints verbatim; pending tasks; current work; optional next step anchored by a verbatim quote of the latest exchange — the anti-drift device). Summary budget raised 2048 → 4096 tokens. (`internal/runtime/compact.go`)
- **Built-in read-only bash auto-allow.** Verifiably read-only commands skip the permission prompt in the prompting modes and in ModeAuto's `RuleClassifier`: conservative parse (any redirection/substitution/heredoc/backgrounding rejects the line; every `&&`/`||`/`;`/`|` segment must independently pass; env-assignment prefixes and path-form commands rejected), core-utility safe-list, and per-subcommand gating for git/gh/docker including `gh api` non-GET detection. Explicit deny rules and plan mode still win. (`internal/permissions/readonly.go`, `internal/permissions/{classifier,manager}.go`)
- **`--system-prompt` / `--append-system-prompt`.** claude-CLI-aligned semantics: replace the authored base (identity + posture + behavioral sections; context sections keep their toggles — combine with `--minimal-prompt` for a bare custom prompt) vs append at the very end of the assembled prompt. On the main CLI and `print-system-prompt`; `/system-prompt set` now feeds the live prompt (`Config.SystemPrompt` was a dead field). (`cmd/claw-code-go/main.go`, `internal/runtime/{config,conversation}.go`, `internal/compat/harness.go`)
- **devbox dev environment.** `devbox.json` (go 1.26 + `build`/`test`/`check` scripts) and `.envrc` for direnv auto-activation. (`devbox.json`, `.envrc`)
- **Configurable client identity (User-Agent + extra headers).** Every provider now sends an honest `User-Agent: claw-code-go/<version>` by default (previously no UA was set at all, so Go's `Go-http-client/2.0` leaked onto the wire — a fingerprint some Anthropic-compatible endpoints, e.g. z.ai's GLM Coding Plan risk-control, penalise as "SDK-based access"). Override precedence: `ProviderConfig.UserAgent` → `CLAW_USER_AGENT` env → default; the ChatGPT-OAuth path keeps its protocol-required `codex_cli_rs/<version>` default but honours the same overrides. New `ProviderConfig.ExtraHeaders` plus **`ANTHROPIC_CUSTOM_HEADERS` env parity with Claude Code** (newline-separated `Name: Value` pairs, explicit config wins) applied last on every request so they can override any default header, User-Agent included; a malformed line is an explicit error, not silently dropped. Wired on anthropic, openai (both auth modes), vertex, and foundry; bedrock keeps the aws-sdk UA (signed requests). Helpers re-exported via `pkg/api` (`Identity`, `ResolveIdentity`, `DefaultUserAgent`, `ParseCustomHeaders`); the dead `apikit.ClientIdentity`/`AnthropicRequestProfile` scaffolding this supersedes is removed. Presenting as another tool is an operator decision between them and the endpoint they target — claw never spoofs by default, and the Anthropic Claude-Code-forfait posture is unchanged. (`internal/api/identity.go`, `internal/api/client.go`, `internal/api/providers/{anthropic,openai,vertex,foundry}/provider.go`)
- **Optional system-prompt sections + minimal-prompt mode.** Every automatic system-prompt section (environment, git status, CLAUDE.md project instructions, auto memory, operating posture, compaction summary, MCP tool list) is now individually toggleable — heavy prompt engineering hurts small models. Three surfaces: a tri-state `"prompt"` settings block (`*bool` fields merged field-wise across layers so an explicit `false` survives; `{"prompt": {"minimal": true, "projectInstructions": true}}` keeps only CLAUDE.md), CLI flags `--minimal-prompt` / `--prompt-sections` (exclusive-enable, implies minimal) / `--disable-prompt-sections` (also on `print-system-prompt` for debuggability), and CLAUDE.md frontmatter keys `minimalPrompt` / `promptSections` / `disablePromptSections`. Section names: `environment`, `git-status`, `project-instructions`, `mcp-tools`, `compaction-summary`, `memory-walk-up`, `memory-imports`, `auto-memory`, `posture` (kebab/camel/underscore all accepted). Defaults all-on — zero behavior change. (`internal/config/{feature,loader,validate,frontmatter}.go`, `internal/runtime/config.go`, `internal/context/assembler.go`, `cmd/claw-code-go/main.go`, `internal/compat/harness.go`)
- **CLAUDE.md ancestor walk-up + `@path` imports (Claude Code memory parity).** Memory discovery now includes CLAUDE.md files from the workDir's ancestor directories (root-most first, most-specific last) and expands `@path` references (absolute, `~/`, relative) recursively — 5 hops max, cycle-safe, skipping fenced code blocks and inline code spans; unreadable targets are silently skipped. Combined cap raised 20KB → 48KB, overridable via `prompt.memoryMaxBytes`. The assembler cache revalidates both discovery candidates (created/deleted files) and every file actually read, imports included. The ancestor walk-up moved to `internal/context.AncestorClaudeMdPaths` (canonical, shared with the slash-command loader). (`internal/context/memory.go`)
- **Persistent auto-memory (MEMORY.md).** New `# Auto memory` system-prompt section injecting the per-workspace memory directory (`~/.claw-code/memory/<workspace-fingerprint>/`, override via `CLAW_MEMORY_DIR`), short maintenance instructions, and the current `MEMORY.md` content (8KB head-truncated). v1 is injection + instructions: the model maintains the file with the standard file tools (`write_file` creates parent directories). Injection is read-only — nothing is created at prompt time; `prompt.autoMemory=false` drops the section entirely. `WorkspaceFingerprint` (FNV-1a, Rust-parity constants) moved to `internal/context` as the canonical implementation with the session store delegating. (`internal/context/automemory.go`)
- **Authored operating-posture section + `pkg/runtime` prompt façade.** New `# Operating posture` section between the identity sentence and the injected context: concision, read-before-edit, targeted edits, convention-following, batched tool calls, git safety (no destructive ops / no commit unless asked), verification honesty, stop-when-done. Original text targeting the same operating qualities as Claude Code — deliberately not a copy. `pkg/runtime` now exposes `PromptConfig`, `DefaultPromptConfig`/`MinimalPromptConfig`, `ResolvePromptSections`, `OperatingPosture()`, and `BuildSystemContext()` (context sections without base/posture) so embedding hosts like iterion compose claw's memory/context without double-posture. (`internal/context/posture.go`, `pkg/runtime/prompt.go`)
- **Claude Opus 4.8 support + Anthropic effort/adaptive-thinking wire fixes.** Registered `claude-opus-4-8` (1M context, 128k output, effort matrix `low/medium/high/xhigh/max` default `high`, adaptive thinking); the bare `opus` alias now resolves to 4-8 and the TUI picker / subagent default models follow. The Anthropic request marshaler (`marshalAnthropicRequest`) now sends effort as **`output_config.effort`** — previously it sent an ignored top-level `reasoning_effort` — defaults **`thinking:{type:"adaptive"}`** on adaptive-thinking models (Opus 4.8/4.7/4.6, Sonnet 4.6), coerces a manual `budget_tokens` request to adaptive (manual budgets 400 on Opus 4.8/4.7), and omits `temperature`/`top_p` (and never forwards `frequency_penalty`/`presence_penalty`) on models that reject them. The interactive loop now actually sends the configured effort (`conversation.go`), and `/effort` + `SetEffort`/`SetReasoningEffort` validate against the active model's matrix (so `xhigh`/`max` are accepted) instead of a hardcoded `low/medium/high`. New `ModelEntry.ThinkingMode`/`RejectsSampling` registry fields and `apikit.AnthropicProfile` / `apikit.ValidateEffortForModel` helpers. Sources: platform.claude.com/docs/en/build-with-claude/{effort,adaptive-thinking}, .../about-claude/models/whats-new-claude-4-8. (`internal/apikit/{model_registry,effort}.go`, `internal/api/{types,client}.go`, `internal/runtime/{conversation,loop_prompt,loop_config}.go`, `internal/commands/ux_cmds.go`, `internal/tools/agent.go`, `internal/tui/model.go`)
- `computer_use` tool with executive action dispatcher: `screenshot`, `left_click`, `right_click`, `middle_click`, `double_click`, `type`, `key`, `mouse_move`, `cursor_position`, `left_click_drag`. Action verbs mirror Anthropic's `computer_use_20241022` spec; the tool emits `api.ImageSource` content blocks for screenshots and structured success descriptions for input actions. Linux/X11-backed via `xdotool` (input) and ImageMagick `import` (capture) — no cgo, no new Go module dependencies. Returns the typed `ErrComputerUseUnavailable` (wrapped, `errors.Is`-detectable) when the host has no display, the required binaries are missing, or the OS is not Linux. The legacy `ScreenshotTool` / `ExecuteScreenshot` façade is preserved and now backed by the screenshot action instead of returning a 501 stub. (`internal/tools/computer_use_exec.go`, `pkg/api/tools/computer_use.go`, `internal/tools/computer_use_test.go`). Closes the `Vision / computer use` parity gap.
- Plugin marketplace remote fetch + verify. New `plugin.RemoteMarketplace` (`plugin/remote_marketplace.go`) exposes `ListPlugins`, `FetchManifest`, and `Install` over a two-tier static layout (`<base>/index.json` advertising plugins, `<base>/<name>/manifest.json` per plugin extending `PluginManifest`). The download → SHA-256 → cosign chain is delegated to `internal/plugins` so the `/store` slash command and the new public API share one verification path. HTTPS-only by default with an opt-in `--insecure-marketplace` / `WithMarketplaceAllowInsecure` escape; metadata documents are size-capped at 1 MiB to defend against hostile servers. New CLI: `claw-code-go plugin install --marketplace <url> [--dest <dir>] [--require-signed] [--insecure-marketplace] [--timeout <d>] <name>` (`internal/compat/plugin_install.go`); honors `CLAW_MARKETPLACE_URL`, `CLAW_PLUGIN_PUBLIC_KEY`, `CLAW_REQUIRE_SIGNED`. Closes the `Plugin marketplace` parity gap. (`plugin/remote_marketplace.go`, `plugin/remote_marketplace_test.go`, `internal/compat/plugin_install.go`, `internal/compat/plugin_install_test.go`)
- Real `ask_user` and `remote_trigger` tools — both were previously stubs in the parity matrix. `ask_user` now exposes an `Asker` interface (`StdinAsker`, `ProgrammaticAsker`, `TUIAsker`) and the schema supports structured `options` (`{id,label}` pairs) and `allow_free_text`. Structured result keys: `status_code`, `success`, `body`, `truncated`, `headers`, `duration_ms`, `error`. Public façade: `pkg/api/tools` re-exports `AskUserQuestionTool`, `Asker`, `Question`, `Option`, `Answer`, `NewStdinAsker`, `NewProgrammaticAsker`, `ExecuteAskUser`, and `ErrNoAsker`. (`internal/tools/{ask_user,remote_trigger}.go`)
- `claw-code-go timeline --session <id>` subcommand renders a saved session's chronological event view. Flags: `--store <dir>` (defaults to `~/.claw-code/sessions`), `--format pretty|json|md` (default `pretty`), `--limit n` (keep last N events; for `json` keeps the last N message records plus session_meta and prompt_history). Each test instantiates the real provider, runs a short streaming request, and asserts that at least one text delta plus a stop event are received; tests skip cleanly when the documented per-provider env vars are missing, so `go test ./...` (no tag) is unaffected. - MCP OAuth Authorization Code + PKCE broker on top of the atomic disk-backed token storage. The broker drives the loopback callback flow (RFC 7636 S256 challenge), exchanges the code at the token endpoint, and silently refreshes near-expiry tokens. Transports plug it in via `broker.BearerHeaderFunc(cfg)` → `TransportConfig.AuthFunc`, so a stale access token triggers an automatic refresh on the next request. Headless callers use `Broker.AcquireNoninteractive`, which returns the typed `ErrReauthRequired` instead of opening a browser when refresh is impossible (no refresh_token, or AS replied `invalid_grant`); transient errors (network, 5xx) propagate verbatim so retry logic can distinguish them. The atomic disk-backed token storage is the persistence layer for the broker. Public façade in `pkg/api/mcp/oauth` re-exports `Broker`, `NewBroker`, `Token`, `Storage`, and `ErrReauthRequired`. ### Fixed

- `dump-manifests` listed a hardcoded five-tool manifest from the first port phase; it now enumerates the real conversation-loop registry (70+ tools), so the diagnostic matches what a session actually registers. (`internal/compat/harness.go`)
- **F-CC-8 — compaction continuation was role `"system"` inside `messages[]`**, which the Anthropic Messages API rejects. It is now an injected user message (wire-safe on every provider, matches how the reference CLI resumes a compacted session); legacy system-role continuations from previously persisted sessions are still parsed. (`internal/runtime/compact.go`)
- **Permission checks judged a 60-char display summary, not the full input.** The check, the approval prompt, `Remember` and ask-rule matching received `summarizeToolInput`'s truncated string, so an approval or allowlist match could never see a mutation hidden past the truncation point; they now receive the full permission subject (display keeps the short form). Raw subjects also reach the classifier under a synthetic `__subject` key — fixing `web_fetch`'s https-only auto-allow, which never saw its URL on this path. (`internal/runtime/conversation.go`, `internal/permissions/{classifier,policy}.go`)
- `print-system-prompt --cwd` now chdirs for real: config layers, the CLAUDE.md walk-up, git status and the environment section reflect the requested directory instead of the process cwd with a cosmetic "Working directory:" line appended. (`internal/compat/harness.go`)
- `claude-sonnet-4-6` static registry entry said 64k max output while upstream catalogs (what the live registry merges on top) advertise 128k — hosts with a fresh live cache failed the static-expectation tests. (`internal/apikit/model_registry.go`)
- `TestBatch3NilRegistries` still expected hard errors from the MCP resource/auth tools on nil registries; those tools deliberately answer with uniform not-found/disconnected shapes since the default-Provider fallback landed. (`internal/runtime/conversation_dispatch_test.go`)
- CLAUDE.md frontmatter `model` / `permissionMode` / `allowedTools` were parsed but never applied; they now overlay `LoadConfig` between settings files and environment variables. YAML frontmatter is also stripped from the injected `# Project Instructions` content — it is config, not instructions, and previously leaked into the prompt. (`internal/runtime/config.go`, `internal/context/memory.go`)
- Tree-wide `gofmt -w` pass to normalize formatting across the module. (commit f409e88)
- BUG 1 — `vertex.MapModelID` now correctly maps canonical Claude model IDs to Vertex AI model strings (was returning the input verbatim for several IDs). (`internal/api/providers/vertex/provider.go`, commit 80f5a8c)
- BUG 6 — `convertTools` no longer silently drops tools with unsupported field shapes; unsupported tools now produce an explicit error so callers can surface the misconfiguration. (`internal/api/providers/openai/responses.go`, commit 80f5a8c)
- BUG 7 — Tool-call args-before-id buffering corrected via the new `sseutil.ToolCallAccumulator`; assistant turns no longer drop arguments that arrive before the tool-call id in OpenAI streams. (`internal/api/sseutil/toolcall.go`, commit 80f5a8c)
- BUGs 2 / 3 — `/v1/responses` interleave assembly for parallel reasoning + tool calls. Each output item now keeps its own block index across the entire stream; opening a `function_call` no longer prematurely closes a sibling `message` text block, so trailing text deltas that resume after a tool call are preserved instead of being dropped on a closed block. Parallel `function_call` items keep arguments correctly partitioned by `item_id` even when their argument deltas are fully interleaved on the wire. (`internal/api/providers/openai/responses.go`)
- 7 additional quality items rolled into the same refactor (validation gaps, error-wrapping consistency, dead branches in SSE decoding). (commit 80f5a8c)
- BUG 4 — Conversation `context.Context` now flows into both the in-process `internal/hooks` `Runner.Fire` and the shell `hooks.HookRunner.Run*` methods. The shell runner uses `exec.CommandContext`, so cancelling the conversation kills any in-flight hook script and surfaces a `Cancelled` result instead of letting the hook outlive the session. (`hooks/runner.go`, `hooks/exec.go`, `internal/hooks/runner.go`, `internal/runtime/conversation.go`)
